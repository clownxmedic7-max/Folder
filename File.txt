1. First learn the Packet Tracer interface
----------------------------------------------------------------
Cisco Packet Tracer is a simulation software used to create and test computer networks without physical networking devices.

How to open a network project:
1. Open Cisco Packet Tracer.
2. Click File -> New.
3. You will see a large white area. This is your workspace.
4. At the bottom-left, you will see device categories:
   - Network Devices
   - End Devices
   - Connections
5. Select a device and drag it into the white workspace.
6. Use the Connections option to connect devices.
7. Use Realtime or Simulation mode to test communication.

Remember these categories:
Device   | Purpose
PC       | Sends and receives data
Switch   | Connects multiple computers
Router   | Connects different networks
Hub      | Broadcasts data to all ports
Server   | Provides services like HTTP and DHCP


2. HUB network - 4 PCs
----------------------------------------------------------------
Question paper Q1
Question: Create a network using only a HUB and 4 generic PCs. Assign IP addresses and send a PDU.

Step 1 - Add devices
1. Open Packet Tracer.
2. Click End Devices.
3. Drag four PCs into the workspace.
4. Name them PC0, PC1, PC2 and PC3.
5. Click Network Devices -> Hubs.
6. Drag one hub into the workspace.

1. Click Connections (lightning symbol).
2. Select Copper Straight-Through.

4. Click Hub -> Port 0.
5. Repeat for the remaining PCs using different hub ports.

Your topology should look like this:
             PC0
              |
     PC1 --- HUB --- PC2
              |
             PC3

Step 3 - Assign IP addresses
Do this for each PC:
1. Double-click PC0.
2. Click Desktop.
3. Click IP Configuration.
4. Select Static.
5. Enter the IP address and subnet mask.

PC  | IP address   | Subnet mask
PC0 | 192.168.1.1  | 255.255.255.0
PC1 | 192.168.1.2  | 255.255.255.0
PC2 | 192.168.1.3  | 255.255.255.0
PC3 | 192.168.1.4  | 255.255.255.0

Step 4 - Send a PDU
1. Change to Simulation mode.
2. Click Add Simple PDU (envelope icon).
3. Click PC0.
4. Click PC3.
5. Click Auto Capture/Play.
6. Observe how the hub forwards the frame to all other ports.

Expected observation:
- Hub broadcasts the incoming frame to all ports except the incoming port.
- All connected computers receive the frame.
- Only the destination computer processes the data.

Conclusion: The hub successfully connects four computers in a star topology.

4. Difference between HUB and SWITCH
----------------------------------------------------------------
(Very important viva question)

HUB                          | SWITCH
Works at OSI Layer 1         | Works at OSI Layer 2
Does not learn MAC addresses | Learns MAC addresses
Broadcasts to all ports      | Forwards based on MAC table
Less efficient               | More efficient
Shared bandwidth             | Dedicated switch port bandwidth
More collisions              | Reduces unnecessary collisions

Easy way to remember:
- HUB = Sends to everyone.
- SWITCH = Sends to the correct destination port.

The two different IP subnets cannot communicate through the switches alone. Once the router is connected and configured, communication becomes possible.

Special question: Divide 192.168.10.0/24 into four equal subnets
You need to borrow 2 bits from the host portion.
- Original subnet: /24
- New subnet: /26
- Subnet mask: 255.255.255.192
- Each subnet has 64 addresses, 62 usable host addresses.

Subnet | Network address | Usable host range | Broadcast
1      | 192.168.10.0    | .1 - .62          | .63
2      | 192.168.10.64   | .65 - .126        | .127
3      | 192.168.10.128  | .129 - .190       | .191
4      | 192.168.10.192  | .193 - .254       | .255

For the four-subnet question, use a router with four available routed interfaces or suitable VLAN/subinterface configuration if the equipment supports it. Connect at least two PCs to each subnet.

9. Static routing
----------------------------------------------------------------
(Important configuration question)
Static routing means manually adding routes to a router.

Example: Two routers connect two LANs.

Step 1 - Add devices
- Two routers (R1 and R2)
- Two switches
- Two PCs
Connect each PC to its switch, each switch to its router, and the two routers through a serial link.

Step 2 - Configure the IP addresses
Device            | IP address
PC0               | 10.1.1.2/24
R1 LAN interface  | 10.1.1.1/24
R1 serial         | 192.168.100.1/30
R2 serial         | 192.168.100.2/30
R2 LAN interface  | 10.2.2.1/24
PC1               | 10.2.2.2/24

PC0 gateway: 10.1.1.1
PC1 gateway: 10.2.2.1

Step 3 - Configure R1
enable
configure terminal

interface gigabitEthernet 0/0
ip address 10.1.1.1 255.255.255.0
no shutdown
exit

interface serial 0/0/0
ip address 192.168.100.1 255.255.255.252
no shutdown
exit

ip route 10.2.2.0 255.255.255.0 192.168.100.2

end

Step 4 - Configure R2
enable
configure terminal

interface gigabitEthernet 0/0
ip address 10.2.2.1 255.255.255.0
no shutdown
exit

interface serial 0/0/0
ip address 192.168.100.2 255.255.255.252
no shutdown
exit

ip route 10.1.1.0 255.255.255.0 192.168.100.1

end

If the serial link's DCE end requires a clock rate, configure it on that end:
clock rate 64000

Step 5 - Verify
show ip route

Then on PC0:
ping 10.2.2.2

Conclusion: Static routes allow the routers to forward packets to remote networks.

Backup static route question
The question paper also has a main route and a backup route.

Example:
ip route 30.0.0.0 255.0.0.0 20.0.0.2 10
ip route 30.0.0.0 255.0.0.0 40.0.0.2 20

- Administrative Distance 10 = Main route.
- Administrative Distance 20 = Backup route.
The lower administrative distance is preferred.


10. RIP routing
----------------------------------------------------------------
RIP means Routing Information Protocol.
It is a dynamic routing protocol. Routers automatically exchange routing information.

Important difference:
- Static routing: Routes are entered manually.
- RIP: Routes are learned automatically.

Steps:
1. Create the topology with three routers connected in a triangle.
2. Connect PC0 to Router0 and PC1 to Router2.
3. Assign the IP addresses from the question paper.
4. Configure all router interfaces with ip address and no shutdown.
5. Configure RIP on all three routers.

Example Router0:
enable
configure terminal
router rip
version 2
no auto-summary
network 10.0.0.0
network 192.168.1.0
end

Example Router1:
enable
configure terminal
router rip
version 2
no auto-summary
network 192.168.1.0
end

Example Router2:
enable
configure terminal
router rip
version 2
no auto-summary
network 20.0.0.0
network 192.168.1.0
end

Use the actual network numbers from the interfaces connected to each router.

Verify:
show ip route

RIP routes are usually marked with R.

Test:
ping 20.0.0.2

Conclusion: RIP automatically learns routes and selects the path based on hop count.

12. What is Wireshark?
----------------------------------------------------------------
Wireshark is a packet-capturing and network-analysis tool.
It captures network packets and displays their protocol details.

Three important sections:
1. Packet List - Displays all captured packets.
2. Packet Details - Displays the selected packet's protocol information.
3. Packet Bytes - Displays packet data in hexadecimal and ASCII.

15. ARP packet capture
----------------------------------------------------------------
Question paper - ARP
ARP full form: Address Resolution Protocol.
ARP is used to find the MAC address corresponding to an IPv4 address on a local network.

Procedure:
1. Open Wireshark.
2. Start capturing.
3. Open Command Prompt as Administrator if required.
4. Clear the ARP cache:
arp -d *
5. Find your default gateway:
ipconfig
6. Ping the gateway:
ping 192.168.1.1
Replace the address with your actual default gateway.
7. Return to Wireshark.
8. Apply this filter:
arp
9. Click an ARP Request.
10. Expand Address Resolution Protocol.
11. Inspect the fields.

Important fields:
Field      | Meaning
Opcode 1   | ARP Request
Opcode 2   | ARP Reply
Sender MAC | MAC address of sender
Sender IP  | IP address of sender
Target MAC | Destination MAC
Target IP  | Destination IP

Viva question: Does ARP have a transport layer header?
No. ARP does not use TCP or UDP. It works directly over the data-link layer.

21. What is Nmap?
----------------------------------------------------------------
Nmap stands for Network Mapper.
It is used to discover live hosts and examine network services.

For your practical, perform scans only against your assigned lab subnet or an authorised practice environment.

A. ARP scan
Question: Discover live hosts using ARP.

Command:
nmap -PR -sn 192.168.1.0/24

Explanation:
- nmap - Starts Nmap.
- -PR - Uses ARP discovery.
- -sn - Host discovery without port scanning.
- 192.168.1.0/24 - Target subnet.
Output: Displays the live hosts discovered in the subnet.

B. ICMP scan
Three types are asked in your question paper.
Type              | Command option
ICMP Echo         | -PE
ICMP Timestamp    | -PP
ICMP Address Mask | -PM

Commands:
nmap -PE -sn 192.168.1.0/24

nmap -PP -sn 192.168.1.0/24

nmap -PM -sn 192.168.1.0/24

Remember:
- PE = Echo
- PP = Timestamp
- PM = Address Mask

C. TCP and UDP ping scan
Scan         | Option | Purpose
TCP SYN Ping | -PS    | Sends TCP SYN probe
TCP ACK Ping | -PA    | Sends TCP ACK probe
UDP Ping     | -PU    | Sends UDP probe

Examples using a permitted lab target:
nmap -PS80 -sn 192.168.1.0/24

nmap -PA80 -sn 192.168.1.0/24

nmap -PU53 -sn 192.168.1.0/24

Important viva:
- TCP SYN Ping does not require a privileged account in the same way ACK probing does.
- TCP ACK Ping normally requires elevated privileges.
- UDP probes to closed ports may produce ICMP Port Unreachable messages.

D. Reverse DNS lookup
The question asks you to compare scanning with reverse DNS disabled and enabled.
nmap -sn -n 192.168.1.0/24

-n = Disable DNS resolution.

nmap -sn -R 192.168.1.0/24

-R = Force reverse DNS resolution.

Difference:
-n                             | -R
Does not perform DNS lookups   | Performs reverse DNS lookups
Usually faster                 | Can take longer
Displays IP addresses          | May display hostnames

Very important viva:
Why is ARP sent before ICMP when the destination is on the same subnet?
Answer: The sender needs the destination MAC address to send the Ethernet frame. ARP obtains that MAC address.

22. Hamming Code - Error Detection and Correction
----------------------------------------------------------------
(Very important)
Aim: To implement error detection and correction using Hamming Code.

What is Hamming Code?
Hamming Code is an error-correction technique used to detect and correct single-bit errors during data transmission.
It adds redundant bits (parity bits) to the original data.

For a 4-bit data word, we use a (7,4) Hamming code:
- 4 data bits.
- 3 parity bits.
- Total = 7 bits.

Remember parity positions:
Position | Bit
1        | P1
2        | P2
3        | D1
4        | P4

# HAMMING CODE - SENDER AND RECEIVER

def encode(data):
    b = [0] * 8
    b[3] = int(data[0])
    b[5] = int(data[1])
    b[6] = int(data[2])
    b[7] = int(data[3])
    b[1] = b[3] ^ b[5] ^ b[7]
    b[2] = b[3] ^ b[6] ^ b[7]
    b[4] = b[5] ^ b[6] ^ b[7]
    return ''.join(str(b[i]) for i in range(1, 8))

def decode(code):
    b = [0] + [int(x) for x in code]
    s1 = b[1] ^ b[3] ^ b[5] ^ b[7]
    s2 = b[2] ^ b[3] ^ b[6] ^ b[7]
    s4 = b[4] ^ b[5] ^ b[6] ^ b[7]
    error = s1 + (s2 * 2) + (s4 * 4)
    if error:
        print("Error at position:", error)
        b[error] ^= 1
        print("Corrected code:",
              ''.join(str(b[i]) for i in range(1, 8)))
    else:
        print("No error detected")
    return ''.join(str(b[i]) for i in [3, 5, 6, 7])

23. Sliding Window Protocol
----------------------------------------------------------------
(Very important)
Aim: To implement flow control using the Sliding Window Protocol.

What is Sliding Window?
Sliding Window is a flow-control technique that allows the sender to transmit multiple frames before receiving acknowledgements.

Example:
Suppose:
- Message = HELLO
- Window size = 3
The sender sends:
Frame 1 -> H
Frame 2 -> E
Frame 3 -> L

After receiving acknowledgements, it sends the remaining frames.

Program
Create sliding.py.

# SLIDING WINDOW PROTOCOL

def sender():
    message = input("Enter message: ")
    window = int(input("Enter window size: "))

    frames = [
        (i + 1, ch)
        for i, ch in enumerate(message)
    ]

    with open("Sender_Buffer", "w") as f:
        for number, data in frames:
            f.write(f"{number},{data}\n")

    print("\nSender Buffer:")

    start = 0
    while start < len(frames):
        end = min(start + window, len(frames))

        for number, data in frames[start:end]:
            print("Frame:", number, "Data:", data)

        # Receiver checks frames and sends ACK
        expected = end
        ack = expected

        with open("Receiver_Buffer", "w") as f:
            f.write(f"ACK,{ack}")

        print("Received ACK:", ack)
        start = end

    print("All frames transmitted successfully")

How to execute
1. Save the file as sliding.py.
2. Run:
python sliding.py
3. Enter 1 for Sender.
4. Enter the message:
HELLO
5. Enter window size:

6. Sender frames are saved in Sender_Buffer.
7. Run the program again and select 2 for Receiver.
8. Receiver reads the frames and saves ACK/NACK information in Receiver_Buffer.

Important: This is a basic file-based demonstration of the sliding-window idea. The sender and receiver are separate runs; a full interactive implementation would repeatedly exchange and verify acknowledgements.

Viva:
- What is flow control? It controls the rate of data transmission.
- What is ACK? Acknowledgement.
- What is NACK? Negative acknowledgement.
- What is window size? Number of frames allowed to be transmitted before waiting for further acknowledgements.

- Destination IP address
- IP version

- TCP destination port

Create sniffer.py:

import socket
import struct

HOST = socket.gethostbyname(socket.gethostname())

try:
    sniffer = socket.socket(
        socket.AF_INET,
        socket.SOCK_RAW,
        socket.IPPROTO_IP
    )

    sniffer.bind((HOST, 0))

    sniffer.setsockopt(
        socket.IPPROTO_IP,
        socket.IP_HDRINCL,
        1
    )

    sniffer.ioctl(
        socket.SIO_RCVALL,
        socket.RCVALL_ON
    )

    print("Packet Sniffer Started...")
    print("Press Ctrl+C to stop")

    while True:
        packet, address = sniffer.recvfrom(65565)

        # IP Header
        first = packet[0]
        version = first >> 4

        # ---- NOTE: the source text ended at the line above. ----
        # ---- The remainder below completes the program.     ----
        ihl = (first & 0xF) * 4
        ttl = packet[8]
        proto = packet[9]
        src = socket.inet_ntoa(packet[12:16])
        dst = socket.inet_ntoa(packet[16:20])

        print("\nIP Version:", version)
        print("Header Length:", ihl, "bytes")
        print("TTL:", ttl)
        print("Protocol:", proto)
        print("Source IP:", src)
        print("Destination IP:", dst)

        if proto == 6:      # TCP
            sport, dport = struct.unpack("!HH", packet[ihl:ihl + 4])
            flags = packet[ihl + 13]
            print("TCP Source Port:", sport)
            print("TCP Destination Port:", dport)
            print("TCP Flags:", bin(flags))
        elif proto == 1:    # ICMP
            icmp_type, icmp_code = struct.unpack("!BB", packet[ihl:ihl + 2])
            print("ICMP Type:", icmp_type)
            print("ICMP Code:", icmp_code)

except KeyboardInterrupt:
    sniffer.ioctl(socket.SIO_RCVALL, socket.RCVALL_OFF)
    print("\nSniffer stopped")
except Exception as e:
    print("Error:", e)
